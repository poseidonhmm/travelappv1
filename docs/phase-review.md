# Reviewing this development phase locally

Use `cd ~/Documents/Wanderly` then `WANDERLY_AI_DISABLED=1 npm run dev` and open http://localhost:3000. This explicit switch prevents any paid OpenAI request while retaining deterministic fallback search. For AI-enabled use with the existing private key, run `WANDERLY_AI_DISABLED=0 npm run dev` instead. Keep the terminal running while using the app. Use a separate browser profile if you want disposable saved-trip edits.

1. On Explore, leave country and date empty, then choose a country by typing its name. The derived region is internal; **Part of the world** continues to select destination regions. Choose a month and reload to check persistence. Check the two fields on desktop and mobile.
2. Search `sunny`. Inspect optional questions, select food or adventure/beaches, then dismiss the questions. Results update without a second search request. Group headings follow the expressed preferences, and no destination repeats across groups.
3. Open Rotorua (`/?destination=rotorua`), Lisbon (`/?destination=lisbon`) or Kyoto (`/?destination=kyoto`). Check named experiences, evidence, price source/date/confidence and pending human review labels. Open an unresearched destination to see the honest pending-research state.
4. Add an experience to Day 3, move it to Day 1, reorder and remove it, and rename a day. Reload to check browser persistence. Change 5/7/10-day outlines; each length retains its own existing v1 saved-plan key. Existing saved generic ideas are retained.
5. Inspect daily and overall **activity** estimates. Rotorua has two usable estimates and one unknown; Lisbon excludes the conflicting castle price; Kyoto has two usable entrance prices. Generic ideas count as unknown. Different currencies and pricing units remain separate.
6. Open Activity review. Inspect record and price flags, edit structured facts or review notes and Save changes. To approve/reject, a human must inspect sources and enter their name. Approve activity and Approve price are independent. Editing approved facts sends them back for review. A concurrent older revision cannot overwrite a newer review. Activity sources are separate from travellers’ saved edits and existing feedback/photo caches.

`data/activities.json` is the versioned seed. Local review overrides live in ignored `data/activity-reviews.local.json`; back that file up independently if needed. The local review API is intended for the loopback prototype, not an authenticated shared editorial service.

Automated validation: `npm test` (mocked AI only) and `npm run validate` (288 destinations plus 7 activities). Evidence and limitations: [activity-evidence.md](activity-evidence.md); architecture and statuses: [activity-system.md](activity-system.md).
